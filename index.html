2026 · Personal project

SAP DELIVER → Databricks Data Product

Simulates a SAP-style data pipeline for the ISC DELIVER domain (shipments, deliveries, warehouse management) landing in Databricks, built with the same functional documentation a real project would carry: business requirements, mapping spec, data dictionary, UAT test cases and a Jira-style tracking board. All data is synthetic — no real SAP system or data is involved.

Bronze, silver and gold Delta Lake tables are built from PySpark notebooks, with a parallel Delta Live Tables / Lakeflow Declarative Pipelines implementation carrying data-quality expectations, both deployed via Databricks Asset Bundles. Incremental ingestion runs through Auto Loader, upserts through MERGE and Change Data Feed, and Unity Catalog governs access down to row-level security by business unit. The gold layer feeds OTIF, lead time and fill rate KPIs, queried via the SQL Statement Execution API for a dashboard.

Used deliberately as a certification-prep build: Time Travel, OPTIMIZE/Z-Order, VACUUM and Liquid Clustering were all exercised against this project's own tables rather than toy examples, with two real mistakes made — and fixed — documented along the way.

2021 · Data Science Bootcamp final project

Job_Offers.fit

Built to help evaluate and prioritize job applications across several EU countries at once, using data science rather than gut feel. It scrapes and scores LinkedIn listings for Data Scientist and Data Analyst roles across 15 countries, then ranks them by fit.

Around 18,000 LinkedIn listings were scraped and enriched with Glassdoor (average salary by title and country, plus company ratings) and Numbeo (cost of living and quality-of-life indices by city). Job descriptions were cleaned and tokenized with NLTK, vectorized with TF-IDF, reduced with PCA, and clustered with KMeans to group similar roles into a content-based recommendation, output as a ranked table.

The main obstacles were practical: scraping errors and account blocks worked around with proxies (APIs would have been cleaner, but cost money and need advance access), and out-of-memory errors that better data cleaning fixed faster than reconfiguring for more RAM.
